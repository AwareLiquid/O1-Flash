# 架构诊断 — 字节级 GRU 基线 vs O1-Flash（banking77，2026-10-19）

> 目的：O1-Flash 在 banking77 上 200K 步 40.8%（4.53M 参数），远低于标准预期。
> 本诊断用**同字节输入、同目标（Brier + decision CE）、同数据**的普通 GRU
> 基线，隔离"数据/字节级"与"编码器架构"两个假设。

## 设置

| 项 | GRU 基线 | O1-Flash（参考） |
|---|---|---|
| 输入 | 字节级（同 `mt_flash.state_tokenizer.encode`，vocab 260） | 同 |
| 参数 | **1.75M**（d=512，1 层 GRU + mean-pool + 线性 77 头） | 4.53M（d256/4L 液态核 + typed heads） |
| 训练步数 | **6,000** | 20K → 37.9% / **200K → 40.8%** |
| 目标 | `calibration_step`（Brier + CE） | 同 |
| 调度 | warmup 500 + cosine→10%，lr 1e-3 | 同 |

## 结果

| 模型 | 步数 | 参数量 | **acc** | ECE (before→after) |
|---|---|---|---|---|
| **GRU 基线** | **6,000** | **1.75M** | **79.06%** | 0.123 → 0.068 (T=2.13) |
| O1-Flash | 20,000 | 4.53M | 37.9% | — |
| O1-Flash | 200,000 | 4.53M | 40.8% | 0.456 → 0.128 (T=4.43) |

## 结论（重要）

1. **架构是瓶颈，不是数据/字节级**：普通 GRU 用 **1/2.6 的参数、1/33 的步数**
   拿到 **79.1%**，接近 O1-Flash 的 **2×**；
2. 字节级输入不是天花板（GRU 同为字节级）；
3. 差距来源候选：
   - **读出方式**：GRU 用 mean-pool + 线性头（对分类最优）；O1-Flash 用 typed
     heads（option-embedding 打分）——对 77 类意图可能信息通路受限；
   - **液态扫描的"抹平"效应**：单/双向衰减扫描把位置信息模糊化，精确内容匹配
     受损（O1-Flash 已有 hybrid_readout 缓解，但仍不足）；
   - **优化难度**：液态核的 4 层 × 13 原纤维 × 5 时间尺度结构在 10k 样本上
     可能欠拟合。
4. **行动建议**：
   - 先做**读出替换 A/B**：O1-Flash 编码器冻结 + 线性/注意力池化头 → 若大幅
     提升，说明是读出问题；
   - 若仍低，考虑编码器替换（液态核 → GRU/注意力）或混合（liquid 状态 + 注意力
     内容通路）；
   - 校准可后续统一做温度缩放（GRU 基线 ECE 0.123→0.068 说明小模型也能校准好）。

## 复现

```bash
python -m benchmarks.baseline_gru_bank77 --steps 6000 --d 512
python -m benchmarks.calibration_eval        # O1-Flash 200K checkpoint 校准评测
```


## 读出替换 A/B（编码器冻结，2026-10-19）

用 200K checkpoint 的**冻结编码器**特征，换掉 typed heads：

| 读出 | acc | ECE (before→after) |
|---|---|---|
| typed heads（原模型） | 40.55% | 0.457 → 0.128 |
| **mean-pool + 线性头** | **46.72%** | 0.155 → 0.044 (T=1.36) |
| attention-pool + 线性头 | 45.03% | 0.178 → 0.063 (T=1.30) |

**判定：编码器特征是主瓶颈**——换头只回收 **+6.1 点**（40.6→46.7），
距 GRU 基线的 **79%** 仍有 32 点差距。即：
1. typed heads 的读出确实有损（~6 点，可修）；
2. 但液态编码器在静态意图分类上的**表征质量**远低于同数据 GRU
   （46.7% vs 79%），这是主要矛盾。

**建议**：决策线若要提精度，优先换/混编码器（液态核 → GRU/注意力，
或 liquid O(1) 状态 + 注意力内容通路的混合）；读出用 mean-pool + 线性头
（顺带 ECE 0.044 已很好）。


## 编码器 A/B（同读出、同预算，2026-10-19 决定性）

两个编码器接**同一个** mean-pool + 线性头，同数据同 2000 步同批大小：

| 编码器 | 参数量 | acc | 训练耗时 (CPU) |
|---|---|---|---|
| **液态核（O1-Flash）** | 1.24M | **17.37%** | 1460s |
| **GRU d=448** | 1.36M | **64.42%** | **157s（9× 快）** |

**结论（决定性）**：在完全受控的条件下，液态核比 GRU 低 **47 点**且慢 **9×**。
结合前两项：
- 完整 O1-Flash（typed heads，200K 步）：40.8%
- 冻结编码器换 mean-pool 头：46.7%（读出损失 ~6 点）
- **液态核 vs GRU（同读出）：17.4% vs 64.4%（编码器是主要矛盾）**

**行动建议**：
1. **决策服务换编码器**：GRU/小型注意力替换液态核（精度 +47 点、速度 9×）；
2. 若保留液态核的价值主张（O(1) 流式状态），做**混合**：液态状态负责流式记忆，
   注意力/GRU 内容通路负责精确分类；
3. typed heads 的读出也应换成 mean-pool + 线性（顺带 ECE 0.044）。
